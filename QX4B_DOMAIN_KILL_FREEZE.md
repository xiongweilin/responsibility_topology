## 1. Centered question

Candidate B is not evaluated by asking only whether a system exhausted a finite candidate list.

The active question is:

> **Can exhaustion of a genuinely finite represented candidate class provide evidence of distinction-space insufficiency, rather than merely failure of that model, option, diagnosis, or negotiation class?**

The critical firewall is:

```text
H_V exhausted
-/->
V inadequate
```

Even perfect finite exhaustion may support only a narrower conclusion such as:

```text
no compatible configuration;
current fault model rejected;
current action set has no feasible member;
current hypothesis family rejected;
current negotiation intersection empty.
```

Candidate B survives only if an additional, source-backed link from the exhausted class `H_V` to the relevant represented distinction space `V` remains after ordinary decomposition. B-K8 is therefore the central kill test of this cycle.

## 3. Enumeration-authority audit

This is an audit field refining existing B-OBS2/B-K1/B-K8. It is **not** a ninth kill test and does not change the QX-3 promotion criteria.

Every domain must classify who or what is entitled to assert that `H_V` is complete for the relevant task position.

Use only:

```text
E1  protocol / grammar / type definition fixes the complete finite set;
E2  formal model generates a complete finite set relative to explicit assumptions;
E3  institutional catalogue claims operational completeness for a bounded task;
E4  analysts/designers merely list currently known or credible candidates.
```

Default evidential strength:

```text
E1: strong for candidate-space completeness, not automatically for V-inadequacy;
E2: strong only relative to the model assumptions that generate H_V;
E3: must audit the institution's authority and task scope;
E4: insufficient for Candidate-B exhaustiveness by default.
```

The audit must distinguish:

```text
epistemically finite list
!=
semantically exhaustive task space.
```

## 4. Catch-all semantics audit

This refines B-OBS6/B-K6 without changing them.

Every domain must distinguish:

```text
Unknown-as-response
!=
Unknown-as-candidate.
```

Examples:

```text
"cannot determine / abort / fail closed"
```

may be a valid task response without being an explanatory hypothesis about reality.

Conversely, a literal `other/unknown` hypothesis inside `H_V` does not automatically explain the world unless its semantics and task obligations make it a genuine candidate.

Mandatory question:

> **Does exhaustion defeat the relied-upon task, or only defeat explanatory identification / successful negotiation inside one candidate class?**

If a safe response already satisfies the task, exhaustion of explanatory or negotiation candidates does not by itself show representation inadequacy.
